## 三个关键决策（需重点确认）

1. **产品定位选的是"多平台运营中台"，不是独立站商城。**
   13 个功能模块中，真正构成壁垒的是 **Landed Cost 引擎 + SKU 级利润核算 + 合规前置校验**。这三个是文档中标注 ★ 的部分，也是排期上必须优先保住的模块。

2. **合规模块被提升为 P0 核心功能，而非附属功能。**
   原因：调研中发现两条会改变产品形态的事实——
   - 美国 800 美元 de minimis 免税门槛已于 2026 年 2 月全球彻底取消，每个包裹需正式报关、HTS 归类与全额缴税；
   - 泰国自 2026 年 1 月 1 日起从第一泰铢起征 7% VAT + 分级进口关税（服装鞋类关税约 30%）。
   因此"落地成本"必须在选品与定价阶段就算准，否则用户会卖一单亏一单。这从"加分项"变成了"生存级功能"。

3. **架构上把"平台适配器层"作为最重要的设计决策。**
   目标：新增一个平台接入，改动范围限定在适配器实现 + 配置，业务层零改动。文档 8.4 节给出了完整的抽象接口代码骨架。

## 需要用户决策/注意的事项

- **平台开发者资质要最早启动**（风险 R2）。Amazon SP-API 需企业资质 + AWS 账号，各平台审核周期不等，建议在动手写代码前就提交申请。文档 M1 之前就应启动。
- **所有税率、关税、平台限流数值都是"配置项"而非硬编码常量**，且文档中明确标注了需以官方来源复核。上线前必须由人工核对并在界面标注数据来源与更新日期。
- **V1 明确不做**：自建 C 端商城、自研 WMS、AI 自动投放、移动端 App、非中文界面。详见文档 2.2 节。
- **12.3 节的"平台合规红线"是产品的责任边界**：系统不提供任何帮助用户刷单、刷评、低报申报价值、规避账号关联的功能。这部分建议在产品设计阶段就固化为硬约束。

## 若时间受限

文档 14.3 节给出了 4 周 MVP 极简方案：只接 1 个平台、只做订单同步 + 批量发货 + 商品库 + **Landed Cost 计算器**（核心卖点不可砍）。其余全部延后。

### 该文档解决的问题

PRD-SRS 第 14 章只给了"12 周 / 6 Sprint"的里程碑名称与完成标志，没回答"每个里程碑具体有哪些任务、需要多少人日、谁来做、容量够不够"。开发规划补齐了这一层：

| 规划内容 | 关键产出（v1.1） |
|---|---|
| 容量核算 | 可用容量 108 人日（120 − 12 联调预留）；P0 全量 **101.7 人日**；**净缓冲 9.3 人日（8.6%）** |
| WBS 拆解 | M0–M6 共 60 条任务，带任务 ID / 产出物 / 人日 / 主责角色 |
| 并行编排 | 12 周甘特（A 后端平台向 / B 算法前端向）+ 关键路径 + 三条延误警戒线 |
| 落地顺序 | 数据库 6 个迁移批次（65 张表）、API 6 个接口批次 |
| 降级路径 | 单人开发不成立（101.7 人日 vs 54 人日容量）→ 走 MVP 4 周方案或延至 20 周 |
| 风险增量 | PRD 12 项风险外新增 7 项：契约漂移、前端人力瓶颈、黄金案例集缺失、缓冲过薄、F11 适配器缺口、凭证申请拖延、**Sandbox 验证不足** |

### v1.1 修订：交付模式改为"开发交付版成品"

用户明确"目前只做开发，上线问题先不考虑，先把成品做出来"。据此做了三件事：

| 动作 | 内容 |
|---|---|
| **资质降档** | 不再申请 Public / 服务商资质，只申请到"能开发"的最低档（注册开发者账号 + 创建 Sandbox/测试应用 + 拿 App Key）。**注意：这一步省不掉**——不拿凭证连 API 都调不了 |
| **上线类工作剥离** | 7 项任务降级或延后，释放 **6.2 人日**（M0-08 监控、M0-10 资质材料、M5-09 发布材料、M6-02 开放 API、M6-03/04/05 部分） |
| **验收口径改写** | 真实店铺授权 → Sandbox 授权；500 并发压测 → 单机冒烟；OWASP 全扫 → 基本安全自查；RTO 演练与亚马逊应用商店上架直接移除 |

### v1.1 修正的一处算术错误（重要）

v1.0 声称"P0 全量 103 人日 / 净缓冲 5 人日"。逐条核算后发现**里程碑标题小计与任务细项不符，合计少算 5.0 人日**：

| 里程碑 | v1.0 标题 | 细项实算 |
|---|---|---|
| M0 | 9.9 | 10.9 |
| M2 | 21 | 23.5 |
| M3 | 19 | 18.5 |
| M4 | 17 | 19.0 |
| **合计** | **102.9** | **107.9** |

即 v1.0 状态下缓冲实际只剩 **3.1 人日（2.9%）**，而非 5 人日。v1.1 已对齐标题与细项，叠加"不上线"释放的 6.2 人日后，缓冲回到 **9.3 人日（8.6%）**。同时修正了前端占比（v1.0 写 42%，实为 **28.3%**）。

### 新增 §1.4：四类边界划分（本次最该看的一节）

"不上线"不等于"能砍的都砍"——有些东西看着像上线问题，实为架构地基：

| 类别 | 含义 | 处理 |
|---|---|---|
| **A 暂缓** | 上线前补做，本轮释放 6.2 人日 | 已列入 **§13 上线前补做清单**（分 3 批，合计 ≈19.5 人日） |
| **B 不可动** | 看似上线问题、实为架构地基：多租户隔离、适配器层、幂等、限流、Decimal、配置化、凭证加密、审计 | **必须现在做**，否则要重写或数据不可信 |
| **C 成品本身** | 全部功能引擎 + 前端页面 + 系统管理（含异步任务中心，调试要靠它） | 不砍 |
| **D 改验收口径** | PRD 15 章中依赖真实店铺 / 生产环境的验收项 | 已逐条改写为开发交付口径 |

# 补充交付：平台开发者资质申请指南

| 文件 | 说明 |
|---|---|
| `docs/平台开发者资质申请指南.md` | 澄清"平台开发者资质"的实质，给出四平台申请要求对比、材料清单、提交顺序与踩坑清单 |

### 核心澄清

**平台开发者资质 ≠ 二次开发，与任何第三方项目代码无关。** 它是一张许可证：平台审核你的**公司主体、官网、隐私政策、数据安全方案、API 用途**，通过后发放一对应用凭证（App Key / App Secret）。

| 分项 | 要点 |
|---|---|
| 本质 | 三方关系：你公司（提交资质）→ 平台（发 App 凭证）→ 卖家（OAuth 授权发店铺 token）→ 你自己写的代码调官方 API |
| 类型选择 | 走服务商路线（SaaS 对外接客）时选 Public / ISV / Third-party Partner；**当前开发阶段只需最低档 Sandbox 应用** |
| Shopee 硬门槛 | 走服务商路线时：中国跨境主体需**营业执照经营范围含"软件开发" + 注册资本 >10 万 RMB**（不满足需工商变更）。**开发阶段是否卡这一条，需在注册页确认**（规划 §10.1 第 0 项） |
| TikTok 陷阱 | **绝不能**用店铺账号邮箱注册，会被判定为卖家且类型不可逆（开发阶段同样适用） |
| Amazon 最深 | Public 路线需过 30+ 题安全问卷 + 三阶段审核 + 上架卖家应用商店 → **本次暂缓**，开发用私有/自授权档 |
| 隐藏工作量 | 申请服务商资质时要求"线上产品证据"（HTTPS 官网 / 隐私政策 / 架构图 / 试用账号）→ 本次已暂缓，上线前补做（§13 批次 1） |

### 开发阶段必须立刻行动的 3 项

1. **注册 4 平台开发者账号 + 创建 Sandbox / 测试应用**（拿 App Key）——审核周期不可控，Week 0 就提交。
2. **域名 + HTTPS 回调地址公网可达**——OAuth 回调没有它跑不通（M0-10）。
3. **20 个 Landed Cost 黄金案例集**——M4 验收的唯一依据，需提前 1 周到齐（N3）。

> ⚠️ 另需准备 **1 个自有真实店铺**：Sandbox 证明不了真实平台行为。规划新增风险 **N7** 要求用真实店铺跑 ≥7 天真实数据做抽样验证。
