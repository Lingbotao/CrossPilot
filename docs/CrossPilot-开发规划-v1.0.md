## 1. 规划前提与容量核算

### 1.1 前提假设（不成立则必须重排计划）

| # | 假设 | 不成立时的后果 |
|---|---|---|
| P1 | 1–2 名全栈开发，全职投入，无外部交付依赖 | 1 人时 12 周不可行，见 §9.1 |
| P2 | 有效开发折算率 90%（预留会议/沟通/环境故障） | 每降 10% 折算率 ≈ 损失 10 人日 |

| P7 | 全流程以 **Sandbox + 真实报文 fixture** 为主验证手段，另用 1 个自有真实店铺做 ≥7 天抽样 | 同步成功率、刊登成功率等指标缺乏可信证据（N7） |

### 1.2 容量 vs 工作量（关键结论）

> **口径统一（v1.1 修正）**：1 人日 = 1 名开发 1 个有效工作日（含自测，不含联调）。
> 毛容量 = 60 工作日 × 2 人 = **120 人日**；扣掉每 Sprint 固定联调/技术债预留（6 Sprint × 1 天 × 2 人 = **12 人日**）后，**可用于功能开发的容量 = 108 人日**。

| 项 | 数值 | 说明 |
|---|---|---|
| 可用于功能开发的容量 | **108 人日** | 120 − 12（联调/技术债预留） |
| P0 功能 WBS 细项合计 | **107.9 人日** | 逐条任务相加，见 §4 |
| 其中 M2-13 单列缓冲 | 3.0 人日 | 不得挪作新功能 |
| **功能净额** | **104.9 人日** | 107.9 − 3.0 |
| **v1.0 状态下的实际剩余缓冲** | **3.1 人日（2.9%）** | 108 − 104.9 |
| "暂不上线"释放（§1.4 A 类） | **+6.2 人日** | 107.9 → 101.7 |
| **v1.1 调整后剩余缓冲** | **9.3 人日（8.6%）** | 108 − (101.7 − 3.0) |

> **⚠️ v1.1 修正说明（必读，影响你的决策）**
> v1.0 声称"P0 全量 103 人日 / 净缓冲 5 人日"。本次用脚本逐条核算后发现：**里程碑标题小计与任务细项不符，合计少算 5.0 人日**（M0 +1.0、M2 +2.5、M4 +2.0、M3 −0.5）。真实工作量是 **107.9 人日**，即 v1.0 状态下的缓冲实际只有 **3.1 人日（2.9%）**，而非 5 人日。
> v1.1 已把标题与细项对齐，并叠加"暂不上线"释放的 6.2 人日，缓冲回到 **9.3 人日（8.6%）**。
> 同步修正：v1.0 称"前端约 43 人日 / 占 42%"，按细项实算 B 方向承担 **约 28.8 人日（28.3%）**，见 §5.3。

> **结论**：调整后 **2 人 × 12 周成立，且留有约 8.6% 缓冲**——这是本次"不保上线"带来的最大收益（缓冲翻 3 倍，从随时击穿回到可承受）。
> 但缓冲仍不宽裕，三条硬性策略继续执行：
> 1. **M2 同步引擎单列 3.0 人日缓冲**（PRD 14.2 明确指出它是全项目最关键路径）；
> 2. **P1/P2 与 §1.4 的 A 类暂缓项一项不做**，任何"顺手加的小功能"直接拒绝；
> 3. **每 Sprint 固定预留 1 天**做联调与技术债（已从容量扣除，不得重复占用）。

### 1.4 开发交付 vs 上线就绪：边界划分（v1.1 新增，核心）

> **背景**：交付模式已确定为"先把成品做出来，上线问题暂不考虑"。
> 但必须警惕一个陷阱：**有些东西看着像"上线问题"，实际是"架构地基"**——它们决定数据是否正确、是否安全，
> 事后补的成本是事前的 5 倍，甚至要推倒重写。本节把全部工作划成四类，逐类给出处理方式。

#### A 类：暂缓（上线前补做）— 释放 6.2 人日

| 任务 | v1.0 人日 | 降为 | 保留什么 / 暂缓什么 | 释放 |
|---|---|---|---|---|
| M0-08 监控骨架 | 1.0 | 0.3 | 保留：`/healthz` + structlog 结构化日志（trace_id/tenant_id 全链贯穿）+ 慢查询日志；暂缓：Prometheus / Grafana / OTel | 0.7 |
| M0-10 平台资质准入材料包 | 1.9 | 0.4 | 保留：域名 + HTTPS/TLS 1.2+ 证书 + **公网可达的 OAuth 回调地址**（缺此授权流程跑不通）；暂缓：官网单页、隐私政策页、数据安全说明、架构图、演示环境与试用账号 | 1.5 |
| M5-09 TikTok 发布材料 | 1.0 | — | 全延后（中英文产品介绍 / 截图 / 演示视频 / 提交文档） | 1.0 |
| M6-02 开放 API + 出站 Webhook + 全量导出 | 1.5 | — | 全延后（`X-Api-Key`/`X-Api-Sign` 体系、租户全量数据导出） | 1.5 |
| M6-03 性能优化 | 1.0 | 0.4 | 保留：索引复核 + 慢查询治理 + 游标分页核对；暂缓：压测报告、并发调优 | 0.6 |
| M6-04 收口验证 | 1.0 | 0.5 | 保留：全量回归 + 8 条主路径 E2E + 基本安全自查；暂缓：500 并发压测、OWASP ZAP 全扫、RTO ≤1h 备份恢复演练 | 0.5 |
| M6-05 交付包 | 1.0 | 0.6 | 保留：9 项交付物文档（PRD 15.3）；暂缓：上线检查清单（PRD 17.3）、灰度上线方案 | 0.4 |

#### B 类：绝对不可暂缓 — 看似"上线问题"，实为架构地基

> 判断标准：**现在不做，以后要么重写，要么开发阶段产生的数据本身就是错的/不安全的。**

| 项 | 为什么不能等 | 归属 |
|---|---|---|
| 多租户三道防线 | 隔离逻辑渗透进每张表、每个 repository；事后加 = 全库返工 + 历史数据污染 | M0-05 |
| 平台适配器层 | "业务层零改动"是新增平台的前提；先写死再抽 = 重写全部业务代码 | M1-05 |
| 幂等键 + UPSERT + 布隆过滤器 | 开发阶段本身就会产生重复单；没有它，测试数据不可信，事后无法清洗 | M2-03 |
| 限流器 + 分级队列 + 重试/DLQ/熔断 | 决定任务会不会丢；开发期就可能被平台封 IP | M2-01/02/04 |
| 全链 `Decimal`（禁 `float`） | 精度损失不可逆，已有利润数据无法回算修正 | 贯穿 |
| 税率/费率配置化 + 版本化 | 硬编码后每次变更都要发版，且无法历史回溯重算 | M4-02 |
| 凭证加密存储 + 令牌自动刷新 | 明文存密钥本身就是漏洞，加密字段迁移代价高 | M1-07 |
| 审计日志 + 权限后端强制校验 | 前端隐藏不是安全边界；审计记录补不回来 | M1-03/04 |

#### C 类：属于"成品"本身，不砍

M2/M3/M4 全部功能引擎（订单同步、批量发货、商品刊登、库存一致性、**Landed Cost 引擎**、合规校验）、全部前端页面（按 §5.3 优先级）、M6-01 系统管理（租户配置中心 / 通知配置 / 审计日志查询 / **异步任务中心** / 系统健康）。
最后一项虽排在 M6，但**开发调试时就要靠它看重试与任务状态**，不能砍。

#### D 类：验收口径必须改写 — 否则"不上线"永远验收不通过

| PRD 15 章原验收项 | 开发交付版口径（本文采用） |
|---|---|
| 授权真实店铺 5 分钟内拉到首笔订单 | **Sandbox 店铺**授权 5 分钟内拉到首笔订单；另用 1 个自有真实店铺抽样验证（≥7 天） |
| 订单同步成功率 ≥99.5% | Sandbox ≥99.5% + 真实店铺抽样 7 天无重复单、无丢单 |
| 500 并发 / P95 ≤500ms | 单机冒烟：10 万单列表 ≤2s、看板首屏 ≤2s、无 N+1 慢查询 |
| OWASP ZAP 全量扫描 | 基本安全自查：跨租户越权（404）、注入、密钥不落盘、依赖漏洞扫描 |
| RTO ≤1h 备份恢复演练 | **延后**至上线前（§13） |
| Amazon 已上架卖家应用商店 | **从交付物中删除** |
| 四平台开发者资质凭证与审核记录 | 改为：**四平台 Sandbox/测试应用已创建，App Key 加密入库** |

> **一句话总结**：不上线 ≠ 不做资质。**注册开发者账号、创建应用、拿到 App Key 是"能开发"的前置条件，一步都省不掉**；
> 能省的只是"服务商资质 + 上线材料 + 运营化能力"这一层。详见 `docs/平台开发者资质申请指南.md`。

## 2. 开发总体策略

| 策略 | 具体做法 | 为什么 |
|---|---|---|
| **垂直切片优先** | M1 结束即打通"注册 → 授权 → 看到第一笔订单"端到端闭环，而非把所有后端横向做完 | 最早暴露真实平台问题（R1/R2） |
| **契约先行，前后端并行** | 每个 Sprint 第 1 天冻结 OpenAPI 契约；前端用 Mock Server 并行开发；每周三、周五两次联调 | 1–2 人时前端无法等待后端 |
| **配置化优先** | 状态映射、税率、限流、枚举、成本项全部落表；硬编码即缺陷 | C5；否则平台一变就要发版 |
| **脚手架里就写好可观测与幂等** | trace_id / tenant_id 进日志；幂等键进基类；限流器进适配器基类 | 事后补的成本是事前的 5 倍 |
| **测试跟着代码走** | 写一个引擎 → 立刻补黄金案例测试；写一个适配器 → 立刻录制真实报文 fixture | PRD 13.2 四类高危用例是 P0 |
| **分支与门禁** | trunk-based + 短分支 + PR；CI 三关（lint/type → test → 覆盖率 ≥70%） | 单人项目也要有门禁，防自我放松 |

### 3.2 环境变量清单（禁止硬编码，C5/NFR-S-02）

| 变量 | 用途 | 备注 |

## 4. 里程碑详细拆解（M0–M6）

> 代号：**A** = 后端/平台方向负责人；**B** = 算法+前端方向负责人。单列人日含前后端。
> 人日口径：1 人日 = 1 名开发 1 个有效工作日（已含自测，不含联调）。

### M0 地基 · Week 1 · 8.7 人日

**目标**：让"写业务代码"这件事本身变得不费力，并一次性钉死多租户隔离。

> **⚠️ 本里程碑只保留"能开发"的最小外部依赖**：域名 + HTTPS 证书 + **公网可达的 OAuth 回调地址**。
> 官网、隐私政策、数据安全说明、架构图、演示环境等资质材料**已暂缓**（§1.4 A 类），上线前补做（§13）。

| ID | 任务 | 产出物 | 人日 | 主责 |
|---|---|---|---|---|
| M0-01 | 仓库与目录脚手架（BE/FE/infra/docs） | 目录规范 + README | 0.5 | A+B |
| M0-02 | `docker compose up` 一键起全栈 | PG16 + Redis7 + MinIO + api + worker + beat + web | 1.0 | A |
| M0-03 | 后端基座：应用工厂、`pydantic-settings` 配置、统一响应/错误码（10xxx–80xxx）、structlog | 可运行 API 骨架 | 1.0 | A |
| M0-04 | 数据库基线与 Alembic：通用 mixin（tenant/audit/soft-delete）+ 租户权限域 8 张表 | 迁移批次 1 | 1.0 | A |
| M0-05 | ★ **多租户三道防线**：ORM 自动注入 + RLS 策略 + 越权测试用例 | 越权测试通过 | 1.5 | A |
| M0-06 | JWT 双 Token + 租户上下文中间件（contextvar，Celery 显式传 tenant_id） | 鉴权骨架 | 1.0 | A |

ROI   = 净利 / (采购成本 + 头程物流分摊) × 100%

## 9. 降级与应急路径

### 9.1 如果只有 1 人（关键判断）

按 §1.2，P0 全量（开发交付口径）≈ **101.7 人日**；1 人全职 12 周仅 54 人日 → **12 周单人不成立**。两条路径：

| 路径 | 做法 | 结果 |
|---|---|---|
| **推荐：极简 MVP（PRD 14.3）** | 只接 1 个平台（Shopee 或 Lazada，审核快）；只做订单同步+列表+批量发货、商品库+单国刊登、**Landed Cost 计算器（不可砍）**、基础看板 | 单人约 5 周出可演示闭环，再按 M4→M3→M5 顺序迭代 |
| 延长周期 | 保持全量 P0，周期延至 20 周 | 交付完整但回本慢 |

### 9.2 其他应急规则

| 情况 | 动作 | 禁止动作 |
|---|---|---|
| 某里程碑超期 >2 天 | 立即砍该里程碑的 P1 页与可视化打磨，保 P0 功能 | ❌ 砍 M2 的幂等/限流；❌ 砍 Landed Cost |
| 平台 Sandbox 应用未批 / 授权跑不通 | 全流程走 **fixture 回放（录制真实报文）+ Mock 平台**，凭证下来只切配置 | ❌ 用非官方 API 抓数据（违反 C6） |
| 平台限流配额低于预期 | 自适应降速 + 拉长同步频率 + 增量替代全量，并在前端显示数据时间 | ❌ 硬编码配额 |
| 合规数据未核实 | 界面标注"数据更新于 X，仅供参考"，功能照常上线但打免责提示 | ❌ 编造税率（R4） |

## 附录 A：成本引擎与利润口径速查（防争议）

| 项目 | 口径 |
|---|---|
| 采购成本 | 采购价(CNY) ÷ 汇率 |
| 头程物流费 | 按渠道计费规则，重量计费与体积重取大者 |
| 进口关税 | 申报价值 × 该国 HS 编码对应税率（查配置表） |
| 进口环节税费 | 按目的国规则（印尼 DPP = 售价 × 11/12） |
| 报关清关固定费 | 报关费 + MPF + ISF + 查验预备金（按国别/渠道配置） |
| 平台佣金 / 支付手续费 | 售价 × 费率（按类目/国别配置） |
| 广告费 | 售价 × 预估 ACOS |
| 退货损失摊销 | 售价 × 退货率 × 损失率 |
| 仓储费 | 体积 × 天数 × 费率 |
| 汇兑预备金 | 成本合计 × 汇率波动预备率 |
| 汇兑损益 | 单列，不计入商品成本 |

> 铁律：**任何不可解释的成本数字都是不可信的数字** —— 每项必须带 `formula` 与 `source`。
