| 项目 | 内容 |

## 1. 这是什么（一句话）

> **"平台开发者资质申请" = 向电商平台的开放平台申请"应用开发者"身份并注册你的应用，让平台承认"这家公司的这个软件有资格替卖家调数据"，然后发给你一对应用凭证（App Key / App Secret 或 partner_id / partner_key）。**

它审的对象是**你这家公司和你这个软件产品的用途**，不是代码。本质是一张**许可证**。

拿到凭证之后，你才有资格走下一步：卖家在自己的店铺后台点"同意授权"，平台才会把该店铺的 access_token 发给你。

---

## 2. 不是什么（三个必须纠正的误解）

### 误解一：要用别人的项目代码做二次开发 ❌

**错。** 与任何第三方项目的源码无关。事实是：

| | 你以为的 | 实际情况 |
|---|---|---|
| 代码来源 | 拿别人的开源项目改造 | **CrossPilot 全程自己写**，一行都不用别人的 |
| 调用方式 | 改别人的代码去对接 | 你自己的代码通过 **HTTPS REST** 调平台官方接口 |
| 申请审什么 | 审代码 | 审**公司主体、营业执照、官网、隐私政策、数据安全方案、API 用途说明** |
| 产出物 | 一份改好的代码 | **一对 App 凭证**（App Key / App Secret）+ 一组被批准的 API 权限（Scope） |

打个比方：这更像去申请企业银行开户或开通支付接口——要交营业执照、说明用途、签协议，然后拿到一个商户号。**没有一行代码是别人的。**

### 误解二：要买 SDK 或源码 ❌

**不用买。** 平台会免费提供**官方 SDK**（如 Lazada 的 `lazop-sdk`、各语言版本的官方示例），那是平台自己维护的工具库，属于"用官方工具"，和"二次开发别人的项目"是两回事。而且 CrossPilot 的技术方案不依赖 SDK——文档 §8.4 走的是自己实现的适配器层，签名算法自己写（Shopee 的 HMAC-SHA256、Amazon 的 AWS SigV4 等）。

### 误解三：个人开发者也能申请 ❌

**做 SaaS 不行。** 关键区分：

| 身份 | 能服务的对象 | CrossPilot 能不能用 |
|---|---|---|
| 卖家自用开发者 | 只能访问**自己店铺**的数据 | ❌ 用不了 |
| 服务商 / ISV / 第三方伙伴 | 可通过 OAuth 访问**多个卖家授权**的店铺 | ✅ **必须走这条** |

CrossPilot 是原生多租户 SaaS（服务 50+ 租户、5000 店铺），所以四个平台**全部必须申请"服务商 / ISV / 公共应用"类型**。选错的后果是只能绑一个店铺，产品定位直接废掉。

> ⚠️ 且 Amazon 明确：个人无法申请公共开发者；Shopee 对中国跨境主体有注册资本硬门槛（见 §6.2）。

## 3. 三方关系（谁给谁什么）

```
① 你的公司 ──提交资质材料──▶ 平台开放平台
                              │
                              ├─ 审核通过 → 发放 App Key / App Secret（你的"应用身份"）
                              │
② 卖家（租户）──在 CrossPilot 点"授权"──▶ 跳平台 OAuth 页 → 点"同意"
                              │
                              └─ 平台发放该店铺的 access_token / refresh_token
                              │
③ CrossPilot 服务端 ──用 App 凭证 + 店铺 token + 签名──▶ 平台官方 API
                              │
                              └─ 返回该店铺的订单 / 商品 / 库存数据
```

三条要点：

1. **App 凭证（你的）与店铺 token（卖家的）是两回事**，缺一不可。
2. **App 凭证里没有"别人的代码"**，只有一对密钥和一个被批准的权限清单。
3. **每个租户授权的店铺都要单独走一次 OAuth**，这也是 PRD 里 `shop_credential` 表存在的意义（每个店铺一套 token，加密存储）。

## 4. 四平台申请要求对比（核心表）

| 项 | Amazon SP-API | Shopee Open Platform | Lazada Open Platform | TikTok Shop Partner Center |
|---|---|---|---|---|
| 申请入口 | Solution Provider Portal（`solutionproviders.amazon.com`） | `open.shopee.com` → Console → App Management | `open.lazada.com` → 开发者注册 | `partner.tiktokshop.com`（美国用 `partner.us.tiktokshop.com`） |
| **必须选的类型** | **Public seller application**（公共卖家应用，OAuth 授权） | 账号类型选 **Third-party Partner Platform** | 应用类型选 **ERP System** | **App developer (ISV)** + **Public App** |
| 类型选错的后果 | 只能自用，无法服务多租户 | 只能管自己店铺 | 授权卖家数上限 60，且需加白名单逐个开通 | 被识别成卖家开发者，只能建 Custom App |
| 主体要求 | **企业主体**（个人不可申请 Public） | 中国跨境主体：**营业执照经营范围须含"软件开发"、注册资本 > 10 万 RMB** | 企业主体 | 企业主体，公司名称须与营业执照一致 |
| 官网要求 | **必须 HTTPS 官网**，符合公共开发者网站指南 | **HTTPS + TLS 1.2+，安全评级 A**，须提供线上产品 URL + 试用账号 | — | 建议提供（非必须） |
| 隐私政策 | 必须（+ 数据保护政策 DPP） | 必须 | 必须（Profile 审核） | 必须（数据安全与隐私问卷） |
| 安全审核 | **最深：30+ 题安全问卷 + 三阶段审核（业务/安全/数据）** | Profile 审核 + 应用信息审核 | Profile 审核 + 应用审核 | 数据安全与隐私问卷 |
| 受限角色/权限 | 订单、库存为普通角色；**买家 PII（姓名/电话/地址）为受限角色，触发深度审核** | 按 API 模块申请，写入类模块需单独审批 | 需为应用申请 API 权限包 | 需逐个申请 Scope；增加 Scope 后卖家需重新授权 |
| 审核周期 | 身份验证 1–3 工作日；**Public 三阶段审核 7–15 天起** | 卖家类 3 工作日；**第三方平台 10 工作日（印尼 14 工作日）** | Profile 审核约 1–3 工作日 | **美/英需合规法务审核 3 周以上**；非美英约 2–3 工作日 |
| 拿到什么 | LWA Client ID / Secret + AWS IAM Role + 角色授权 | `partner_id` + `partner_key` | `app_key` + `app_secret` | App Key + App Secret + **Service ID** |
| 特殊坑 | **Public 应用必须上架 Amazon 卖家应用商店**；开发者资料申请需 <500 字且原创，不得抄官方政策原文 | 注册邮箱一旦提交不可修改；须通知 Account Manager | 测试态限额 1 万次/天、token 7 天；**申请上线要求调用成功率 > 85%** | **ISV 注册绝不能用店铺账号邮箱**（会被识别成卖家）；**强制服务器出口 IP 白名单** |

## 5. 逐平台关键动作

### 5.1 Amazon SP-API（周期最长，必须最优先）

| 步骤 | 动作 | 备注 |
|---|---|---|
| 1 | 注册 Solution Provider Portal 账户，完成邮箱 + 手机 + 法人身份验证 | 2026 起含人脸识别 |
| 2 | 创建 Developer Profile，数据访问类型选 **Public** | 申请内容需 <500 字原创，模糊描述会被驳回 |
| 3 | 申请 API Roles | 订单/库存/报表为基础；**买家 PII 为受限角色，会触发三阶段审核** |
| 4 | 填写安全问卷（30+ 题） | 覆盖传输/存储加密、IAM 与密钥管理、访问控制、日志审计、数据保留与删除、泄露响应、第三方共享 |
| 5 | 准备 AWS 账号与 IAM Role | 调 SP-API 需 SigV4 签名（PRD §8.4 已写明） |
| 6 | 上架 Amazon 卖家应用商店 | Public 开发者的义务，不是可选项 |

**对我们的直接影响**：Amazon 是四个平台里唯一**要求把安全方案写成文档并通过审计**的。M0 的"多租户三道防线 + 凭证 AES-256-GCM 加密 + 日志脱敏 + 审计日志"正好就是这份问卷的答案——所以 M0 的工程基线不只是技术需要，**还是申请材料**。

### 5.2 Shopee（有中国主体硬门槛）

**中国跨境（CB-CN）开发者的额外要求（官方明列）**：

- [ ] 营业执照**经营范围必须包含"软件开发"**
- [ ] **注册资本必须高于 10 万人民币**
- [ ] 必须**告知你的 Account Manager**（有没有对接的客户经理要先确认）

**其他要点**：
- 应用提交时需提供**线上可访问的产品 URL（HTTPS + TLS 1.2+）+ 试用账号并开放全部功能**，且网站安全评级需为 "A"
- 审核周期：第三方平台 10 工作日（印尼 14 工作日）
- 注册邮箱提交后不可修改，选企业邮箱

> ⚠️ **这条最可能卡住项目**：如果主体经营范围没写"软件开发"或注册资本不足 10 万，必须先走工商变更或调整主体，这是**数周级的行政流程**，越早确认越好。

### 5.3 Lazada（最快，但上线有条件）

| 要点 | 说明 |
|---|---|
| 应用类型 | **选 ERP System**（默认可授权 300 个卖家，可按需申请提升）；不要选 Seller in-house APP（默认 20、上限 60，且每个卖家要加白名单） |
| 创建流程 | 先点 **Apply** 等审批 → 审批通过自动获得一个"测试状态"应用 → 再点 **Create APP** |
| 测试态限制 | 调用上限 1 万次/天；access_token 7 天；refresh_token 14 天 |
| 线上态限制 | 调用上限 1000 万次/天；access_token 30 天；refresh_token 180 天 |
| **上线条件** | **调用成功率需 > 85%** 才可申请转线上 |
| 凭证位置 | App Console → App Management → Manage → Advanced Information → View |

> **我们的影响**：Lazada 的"测试态 token 只有 7 天、refresh 只有 14 天"这条，会让 M1 的令牌刷新任务在测试阶段就要频繁验证。而且"成功率 >85% 才能上线"意味着 **M2 的错误处理与重试质量直接决定能否拿到生产权限**——这是 M2 必须做扎实的又一个理由。

### 5.4 TikTok Shop（有两个容易踩死的点）

**① 注册邮箱决定开发者类型，且不可逆**

- 想注册成 **ISV / App developer**：**绝对不能用店铺账号的邮箱**
- 用了店铺邮箱 → 系统判定你是卖家 → 只能注册成 Seller developer → 只能建 Custom App，无法服务其他卖家
- 若已经用错邮箱：需提工单或联系 Account Manager 申请加白名单后才能继续

**② 美/英市场要过合规法务审核，3 周以上**

- 目标市场若含美国/英国，合规与法务审核是"长杆环节"，官方明确建议提前规划
- 注册时需选 Registration region（须与公司营业证明一致）与 Target market（中国/中国香港注册主体可选 UK、MY、VN、TH、PH、SG）

**其他**：
- 创建应用时填 App 名称、类目、Logo、目标市场、卖家类型，以及 **Redirect URL** 和 **Webhook URL**（两个都要，Webhook 用于订单/库存实时推送，对应 PRD §10.5）
- 应用类型：**Public**（上架 App Store 供所有商家使用；CrossPilot 选这个）
- 应用达到 **25 个卖家授权**后会触发 TikTok 的应用复审——规模化前要留时间
- 产出三个凭证：App Key、App Secret、**Service ID**（授权链接是基于 Service ID 拼的）
- **API scope 需要在应用详情页逐个开启**；若在卖家授权之后再新增 scope，卖家必须**重新授权**才能访问新数据

## 6. CrossPilot 需要额外准备的"资质准入材料包"（隐藏工作量）

**这是原开发规划里漏掉的一块。** 四个平台的申请都要求提交"线上产品证据"，而产品在 M0/M1 之前还不存在——所以必须先做一层**最小可用的资质包装**，否则整个申请链路会被阻塞，M1 直接延期。

| # | 材料 | 服务的平台 | 归属 | 人日 |
|---|---|---|---|---|
| 1 | HTTPS 域名 + 证书（TLS 1.2+、安全评级 A，含 HSTS 等配置） | Amazon / Shopee 硬性要求，兼作 OAuth 回调域名 | M0 | 0.5 |
| 2 | 单页官网（产品定位、功能截图、联系方式） | Amazon Public / Shopee ISV / TikTok ISV | M0 | 0.5 |
| 3 | 隐私政策页 | 四平台全部要求 | M0 | 0.3 |
| 4 | 数据保护与安全说明（加密 / 访问控制 / 日志审计 / 数据保留与删除 / 泄露响应） | Amazon DPP 问卷 + TikTok 数据安全问卷 | M0 | 0.3 |
| 5 | 系统架构图 + 数据流图 | Amazon Public 申请必备 | M0 | 0.3 |
| 6 | 可登录演示环境 + 试用账号（功能可用） | Shopee ISV 要求"提供线上 URL + 试用账号" | M0–M1 | 0.5 |
| 7 | Redirect URI 回调端点实现 | 四平台 OAuth 都要求（已含在 M1-06） | M1 | — |
| 8 | 英文产品介绍 + 截图 + 演示视频 + PRD 文档 | TikTok ISV 发布审核 | M5 末 | 1.0 |

**小计**：M0 新增约 **1.9 人日**（第 1–5 项）+ M0/M1 第 6 项 0.5 人日 + M5 末 1.0 人日。

> 待办：这 1.9 人日需要计入 M0 估算（原 8 人日 → 约 9.9 人日），全局缓冲相应收窄。已同步登记到开发规划文档。

## 7. 提交顺序与时间倒推

按"审核周期长 → 先提交"排序，**四家可以并行提交，不要串行做**：

| 优先级 | 平台 | 提交时点 | 理由 |
|---|---|---|---|
| P0 | **Amazon SP-API（Public）** | 立即（Week 0） | 审核最深、周期最长（三阶段 7–15 天起 + 安全问卷往返），且依赖 AWS 账号准备 |
| P0 | **TikTok Shop（ISV）** | 立即（Week 0） | 美/英合规法务审核 3 周以上 |
| P1 | **Shopee**（第三方平台） | 立即启动，但先确认主体门槛 | 需先自查营业执照经营范围与注册资本；审核 10 工作日 |
| P2 | **Lazada** | Week 1–2 | 审核最快（1–3 工作日）；且上线有"成功率 >85%"的条件，反而不急于拿生产权限 |

**绝对不要做的事**：等产品开发完再申请资质。四个平台的审核周期合计可能超过 M1+M2 的长度，串行做必然延期。

## 8. 立即行动清单

**本周（与 M0 并行，不占开发人日）**

- [ ] 确认公司主体：营业执照经营范围是否含"软件开发"、注册资本是否 > 10 万 RMB（**Shopee 硬门槛**）
- [ ] 注册 Amazon Solution Provider Portal，开始 Developer Profile 填写与法人身份验证
- [ ] 注册 TikTok Shop Partner Center，**用企业邮箱（绝不能用店铺邮箱）**，选 App developer (ISV)
- [ ] 注册 Shopee Open Platform 开发者账号（用企业邮箱，提交后不可改）
- [ ] 注册 Lazada 开发者账号，完善 Profile 提交审核
- [ ] 确定并固定服务器出口 IP，登记各平台白名单（TikTok 强制）
- [ ] 准备 AWS 账号与 IAM Role（Amazon SigV4 签名依赖）
- [ ] 校验服务器 NTP 时间同步（Shopee 时间戳偏差 >15 分钟直接认证失败）
- [ ] 分配域名 + 申请 HTTPS 证书，规划回调地址（如 `/api/v1/shops/callback/{platform}`）

**M0 期间（开发任务，约 1.9 人日）**

- [ ] 官网单页 + 隐私政策页 + 数据安全说明页
- [ ] 系统架构图 + 数据流图（可直接复用 PRD §8.1 架构图，改用英文标注）
- [ ] TLS 配置达标（TLS 1.2+ / HSTS / 安全评级 A）
- [ ] 演示环境与试用账号

## 9. 踩坑清单

| # | 坑 | 后果 | 规避 |
|---|---|---|---|
| 1 | 开发者类型选成"卖家自用" | 只能服务 1 个店铺，SaaS 定位失效 | 四平台一律选服务商/ISV/Public；CrossPilot 是多租户 SaaS |
| 2 | TikTok 用店铺账号邮箱注册 | 被判定为卖家，类型不可逆 | 必须用企业邮箱 |
| 3 | Shopee 主体经营范围不含"软件开发"或注册资本 <10 万 | 无法通过审核 | 立即自查，必要时工商变更（数周级） |
| 4 | 等产品做完再申请 | M1 授权验收项必然延期 | Week 0 并行提交 |
| 5 | 只申请基础角色/Scope，上线后再补 | 受限角色（PII）触发深度审核；TikTok 加 scope 需卖家重新授权 | 一次性把订单/库存/商品/PII 角色申请齐 |
| 6 | 没准备官网/隐私政策/架构图 | Amazon Public、Shopee ISV 直接驳回 | 按 §6 清单在 M0 做齐 |
| 7 | 服务器出口 IP 未固定 | TikTok 授权失败 | 先固定出口 IP 再登记白名单 |
| 8 | 亚马逊开发者资料抄官方政策原文 | 明确会被驳回（要求原创、<500 字） | 用自己的业务语言描述 |
| 9 | 忽略"上线申请"这一步 | 一直停留在测试态（Lazada 1 万次/天、token 7 天） | 提前把调用成功率做到 >85% 并提交转线上 |
| 10 | 把审核周期算进开发缓冲里 | 缓冲被吃掉 | 资质申请是**并行行政流程**，不占开发人日，但必须早启动 |

## 10. 一句话总结

> **平台开发者资质 = 一张许可证 + 一对应用密钥，不是代码。**
> 要证明的是"你这家公司有资质、这个软件有正当用途、数据会安全保管"；
> 与"用别人的项目代码二次开发"没有任何关系——CrossPilot 的适配器层、同步引擎、Landed Cost 引擎全部自研。
